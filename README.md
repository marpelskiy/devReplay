# ⏪ dev-replay

**Локальная машина времени для твоего кода. Без гита, без боли, на лету.**

Представь, что у твоего редактора кода появился видеорегистратор (или черный ящик). Ты просто запускаешь его в фоне и идешь кодить. Он тихо пишет каждое твое сохранение файла. Если ты случайно сломал проект, стер нужный кусок кода или ушел не в ту степь — ты просто вводишь время, когда «всё работало», и получаешь срез своего кода из прошлого в отдельной папочке.

## 🤬 Знакомые боли, которые решает `dev-replay`

* **Лимит `Ctrl+Z` исчерпан или редактор закрыт.** Ты написал крутой алгоритм, потом решил его отрефакторить, всё сломал, случайно закрыл вкладку в VS Code... и история отмены стерлась. `dev-replay` помнит всё.
* **«Я поменял только одну строчку, почему всё упало?!»** Ты не помнишь, где именно опечатался пять минут назад. Смотришь в `dev history` и видишь точный лог всех своих изменений по секундам.
* **Мусорные коммиты.** Чтобы не потерять рабочий кусок кода перед экспериментами, мы часто делаем коммиты вроде `test`, `wip`, `asdasd`. С этим тулзом это больше не нужно: экспериментируй смело, код бекапится при каждом `Ctrl+S`.
* **Страх всё сломать при восстановлении.** Инструмент **никогда** не перезаписывает твои текущие рабочие файлы. Когда ты просишь вернуть код из прошлого, он аккуратно складывает его в изолированную папку `time_machine`. Твой сломанный код тоже остается при тебе.

## 🛠 Как установить (занимает 1 минуту)

Для работы нужен только Python 3.

**1. Скачиваем тулзу к себе на комп:**
Желательно положить её куда-нибудь в домашнюю директорию, чтобы она всегда была под рукой.

```bash
cd ~
git clone https://github.com/твое-имя/dev-replay.git
cd dev-replay

```

**2. Настраиваем окружение (рекомендуется):**
Чтобы не засорять систему, создадим локальное виртуальное окружение и поставим туда `watchdog` (библиотека, которая следит за файлами).

```bash
python3 -m venv venv
source venv/bin/activate
pip install watchdog

```

**3. Создаем глобальную команду `dev`:**
Чтобы ты мог вызывать магию из любой папки любого проекта, добавим алиас в твой терминал.
Открой конфиг терминала (например, `~/.zshrc`, `~/.bashrc` или `~/.config/fish/config.fish`) и в самый низ добавь эту строку:

```bash
alias dev='python ~/dev-replay/start.py'

```

*Не забудь перезапустить терминал (или прописать `source ~/.zshrc`).*

## 📖 Подробный гайд: Как юзать?

У тебя есть всего 3 команды. Работать с ними нужно **находясь внутри папки твоего проекта** (того, который ты сейчас кодишь).

### Шаг 1: Включаем запись

Открываешь терминал в папке проекта и пишешь:

```bash
dev log

```

Скрипт спросит путь, просто **нажми Enter** (он сам поймет, что ты уже в нужной папке).
Всё, можешь сворачивать этот терминал. Инструмент будет висеть в фоне и логировать каждый раз, когда ты сохраняешь файлы (`.py`, `.js`, `.html` и т.д.). Системные папки типа `.git` или `node_modules` он игнорирует, так что комп тормозить не будет.

### Шаг 2: Смотрим, что натворили

Допустим, код сломался. Ты хочешь понять, что делал последние полчаса. Открываешь новую вкладку терминала и пишешь:

```bash
dev history

```

**Ты увидишь примерно это:**

```text
последние 15 действий:
[20:12:05] api.py -> добавил: 'def fetch_data():' (строка 10)
[20:15:22] config.json -> удалил: '"debug": true' (строка 4)
[20:18:40] main.py -> добавил: 'print("test")' (строка 42)

```

Сразу становится понятно, когда всё пошло не так.

### Шаг 3: Перематываем время ⏪

Ты понял, что в `20:15` проект еще жил. Воскрешаем его:

```bash
dev replay

```

* Скрипт снова спросит путь — жмем **Enter**.
* Спросит время — вводим **`20:15`** (или с секундами `20:15:22`).

**Что произойдет?**
В корне твоего проекта появится скрытая папка `.dev-replay/time_machine/`. Внутри неё будет лежать точная копия твоего проекта (только те файлы, которые ты менял), ровно в том виде, в котором они были в 20:15. Берешь оттуда нужный кусок кода, вставляешь в свой сломанный файл — и идешь пить кофе.

## ⚙️ Под капотом (и пара важных правил)

1. **Где хранятся логи?** Внутри твоего проекта создается скрытая папка `.dev-replay`. В ней лежит файл `log.jsonl`.
2. **Как не слить логи на GitHub?**
**ОБЯЗАТЕЛЬНО** добавь папку `.dev-replay/` в `.gitignore` твоего проекта, чтобы случайно не запушить всю эту историю изменений в публичный репозиторий.
3. **Очистка.**
Если проект долгий, лог-файл может разрастись. Если история тебе больше не нужна, просто удали папку `.dev-replay` ручками, и при следующем запуске `dev log` всё начнется с чистого листа.

📂 Структура папок

Как инструмент интегрируется в твой проект:
Plaintext

твой_проект/
├── src/
├── main.py
├── ...
└── .dev-replay/                 <-- Скрытая папка, создается автоматически
    ├── log.jsonl                <-- Лог всех действий и снимков кода
    └── time_machine/            <-- Появляется только после "dev replay"
        ├── src/                 
        └── main.py              <-- Твой восстановленный код из прошлого

*Сделано для того, чтобы сберечь нервы разработчиков.* ☕️
